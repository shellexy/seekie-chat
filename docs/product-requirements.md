# Seekie Chat · Linux LLM 聊天客户端需求草案

版本：0.3 · 日期：2026-10-12 · 状态：需求完善中，可作为开发基线

## 1. 产品目标与范围

面向 Linux 桌面的本地优先、多供应商 LLM 聊天客户端。采用接近 ChatGPT 的交互习惯，默认浅色主题；聊天记录、配置和附件保存在本地，使用用户配置的远程 API 完成模型推理和搜索。

首版建议采用 Electron + TypeScript。首版不包含账号系统、云同步、多人协作、本地模型部署、任意插件执行和自动操作电脑。

当前交付范围仅为 Linux 本地开发运行：安装依赖后通过开发命令启动 Electron 桌面窗口。暂不考虑安装包、发行版打包、签名、应用商店发布和自动更新。

“预设”仅提供供应商配置模板，不附带 API Key，不承诺所有兼容服务支持相同功能。本文中的可选功能可以分阶段实现。

## 2. 页面与布局

### 2.1 主界面

- 三栏布局：左侧会话列表、中间消息区、右侧对话大纲。
- 默认浅色主题，设置中支持浅色、深色、跟随系统；提供字号和内容宽度设置。
- 左右侧栏可折叠、可调整宽度；窗口较窄时优先保留中间消息区。
- 左侧顶部固定新建会话及搜索入口，底部固定归档视图和设置入口；会话列表在自己的区域内上下滚动。
- 浮动反馈提示显示在窗口正中间；聊天模型选择器和顶栏显示“模型名称 | 连接名称”；AI 回答不显示头像和前置模型标签，操作按钮右侧合并显示“模型名称·YYYY-MM-DD HH:mm · 输入 · 输出”，悬停、聚焦或点击在同一个浮窗内依次显示模型名字、模型提供方、思考等级与角色预设名（同一行）、日期时间与用量指标；用量指标含总耗时、端对端速度、生成速度与首 Token 生成时间；生成速度在端对端速度的基础上再扣除工具调用与首 Token 等待时间；正文、推理与工具调用都算输出，思考的生成时间仍计入分母（旧消息没有该值时退回首字耗时）；思考等级与角色预设名取该条回答生成时记下的配置（不是分支当前值），认不出则不显示；用户提问下方在复制按钮左侧显示日期时间。输入框隐藏模型选择与思考等级前的图标，effort 思考选项直接显示原始等级值。GPT 新增模型的思考等级包含 `xhigh` 和 `max`，DeepSeek 为 `low`、`high`、`max` 三档。
- 中间顶部以单行显示会话标题、当前模型和分支操作；输入框固定在底部，隐藏底部回答免责声明，支持通过顶部拖动条调整高度（最大为窗口高度的 45%，不超过 420px），消息区域独立滚动。模型选择、思考等级、会话选项和联网开关放在输入框下方，与发送按钮同一行并位于其左侧。
- 右侧大纲独立滚动，点击条目定位相应消息，高亮当前阅读位置。
- 流式生成时，用户停留在底部则自动跟随；用户向上阅读则停止跟随，提供“回到底部”。
- 空会话、加载中、错误、无搜索结果、无模型配置等状态提供明确反馈。

### 2.2 会话列表

- 支持新建、打开、重命名、删除、按标题搜索和归档；可切换查看已归档会话，并随时取消归档。
- 默认按最后一条聊天消息的更新时间倒序排列，后台标题生成不改变排序。
- 手动改名立即保存，并且不再被后台自动生成标题覆盖。
- 删除支持确认或短期撤销；需明确是否同时删除已无其他引用的附件。
- 中文长标题截断显示，悬停可查看完整标题。

### 2.3 对话大纲

- 每轮问答分别显示用户消息和助手回答的第一条非空文本行；去除 Markdown 标记并截断长文本。
- 图片提问没有文字时，显示“图片提问”；工具输出不单独占据主大纲条目。
- 首行是代码块或表格时使用可读占位摘要；未完成的回答标记“生成中”。
- 大纲仅展示当前分支中的消息，保留轮次、角色及版本提示。
- 分支切换后大纲同步更新；分叉位置显示分支数量及切换入口。

### 2.4 设置页面

- 设置页顶栏与对话页顶栏同高、单行：左侧返回按钮与“设置”标题（旁注当前设置项），右侧显示保存状态与窗口控件。
- 没有“保存设置”按钮：改动先落在页面的草稿里，切换设置项或离开设置页面时自动写盘，写盘后弹一条“已经自动保存”；顶栏显示“自动保存”，有未写盘的改动时显示“未保存”，写盘过程中显示“保存中…”，成功后短暂显示“已保存”。
- 写盘失败时草稿留在页面上并弹出失败原因，用户改完再切换一次即可；不会因为一次失败就丢掉已填的内容。
- 页面被别处关掉时（侧栏切换会话、新建对话）同样写盘；导入备份后不写回页面里的旧草稿，以免覆盖刚恢复的数据。
- 模型服务页在还没有任何连接时，空状态下方提供一行文字链接“还没有 API？点击一键添加免费体验模型”；点击后添加 `OpenRouter·Kilo` 连接（OpenAI 兼容协议、`https://api.kilo.ai/api/openrouter`、密钥 `anonymous`）与 `Auto Free` 模型（模型 ID `kilo-auto/free`，上下文 256,000 token、最大输出 65,536 token，启用图片输入与工具调用，思考参数为思考等级、默认 `low`）并立即写盘。新建对话页的“连接第一个模型”按钮下方提供同一个入口。

## 3. 供应商、模型与设置

### 3.1 接口协议

分别实现四个协议适配器：

1. OpenAI Chat Completions API。
2. OpenAI Responses API。
3. Anthropic Messages API。
4. Gemini GenerateContent API（原生流式、图片、思考摘要、Google Search 和外部搜索工具调用）。
5. Ollama 本地服务和 Ollama Cloud 的 OpenAI Chat 兼容接口。

支持官方服务预设及自定义兼容服务。所有连接新增模型时，思考参数默认选择思考等级（effort）；所有等级列表都含 `none`，它是明确关闭思考的一等档位（DeepSeek 与 Ollama 都这样定义），与 `auto` 不同：`auto` 只表示不发送 `reasoning_effort`，而 DeepSeek 的 `thinking` 默认 `enabled`、Ollama 未指定时还会自动开启思考，故只有 `none` 能真正关闭。默认档位为 `none, minimal, low, medium, high`，GPT 为 `none, low, medium, high, xhigh, max`，DeepSeek 按官方文档为 `none, low, high, max`，不再与 GPT 对齐。默认起始档位 `high`（官方文档说明 DeepSeek 的默认档位亦为 `high`），预设、手动添加与从服务端列表添加三条路径一致；服务端若把 `none` 报成默认档位则忽略，隐式兜底也永不选中 `none`。通过 OpenAI 兼容连接添加名称含 `gemini` 的模型时，默认勾选图片输入与工具调用。上下文窗口默认为 1,000,000 token、最大输出默认为 65,536 token；供应商预设模型保留其专门配置。DeepSeek 提供 Anthropic、OpenAI 兼容与 Responses 三种协议，仅 Anthropic 协议提供服务端内置搜索，且该搜索按官方说明自 2026 年 11 月 1 日起按次收费。因此提供两个预设并把 OpenAI 兼容协议作为默认：“DeepSeek”使用 `chat` 与 `https://api.deepseek.com/`（自动拼成 `/v1/chat/completions`），搜索改用显式的 DeepSeek 搜索接口，调用次数与费用可见；“DeepSeek·Anthropic”使用 `anthropic` 与 `https://api.deepseek.com/anthropic`，保留原生搜索。两者均自动添加 `deepseek-flash`（展示名称为“DeepSeek-Flash”，模型 ID 仍为 `deepseek-flash`），上下文 1,048,576 token、最大输出 393,216 token（384K），取服务端 `/models` 报告的值，启用图片输入与工具调用，思考参数默认选择思考等级（effort）；仅 Anthropic 预设勾选原生搜索。预设改动不影响已存在的连接——连接各自保存自己的协议。每个连接配置包含：名称、协议、Base URL、API Key、可选自定义请求头、超时和代理策略，另有一个启用/禁用开关。以 OpenAI 兼容协议连接时默认开启“GPT 模型自动使用 Responses 协议”，可随时关闭：模型 ID 形如 `gpt-6-astra`、`gpt-6-luna`、`gpt-6.1-sol` 的模型改用 Responses 协议，以支持推理摘要等新特性，`gpt-oss` 等不匹配的模型仍走原协议；该选项只在 OpenAI 兼容协议下出现。OpenAI 预设名为“OpenAI”且默认使用 Responses 协议，不再单列 Chat Completions 预设；需要时可在连接里改协议。自定义请求头中的认证信息按密钥处理。禁用的语义是“不参与选择”而非“拒绝发送”：配置与模型保留，不再出现在模型选择器的三组列表中，新对话的默认模型与最近使用都会跳过它，连接标签变淡并带点；已有会话仍可继续使用，因为历史消息引用的是模型而不是连接。开关可逆、无确认框。所有连接都被禁用时新对话退回原顺序，避免界面退化为没有模型可选。旧数据没有该字段，加载时一律视为启用。

Gemini 预设使用 `https://generativelanguage.googleapis.com/v1beta`，认证使用 `x-goog-api-key`；模型列表支持分页并只展示可生成内容的模型。Gemini 3 及以上可配置思考等级，Gemini 2.5 可配置思考预算；原生搜索使用 Google Search，保存服务返回的来源和思考签名。

Ollama 预设使用 `http://localhost:11434/v1`。Ollama Cloud 使用 OpenAI Chat 兼容协议和 `https://ollama.com/`，并预置 `gemma4:31b`，上下文窗口与最大输出均为 256,000 token，启用图片、工具和视频输入。该模型没有已知的思考参数，默认选择 effort，等级为 `none, minimal, low, medium, high`。注意 gemma4 只认思考等级：改用思考预算会导致完全不思考，也看不到思考摘要。上下文窗口允许与最大输出相等。

Base URL 规范化及实际请求路径必须明确，不重复拼接 `/v1`；提供测试连接并显示脱敏错误。模型列表支持服务端获取和手动添加，获取失败不阻止手动配置。“添加服务端模型”对话框的模型列表上方提供搜索框，按展示名或模型 ID 过滤并显示匹配数，筛选为空时列出全部；“全选”只作用于当前筛选出的模型。

每个模型保存其所属连接、模型 ID、展示名称，以及上下文窗口、最大输出和能力配置。不要只根据模型名字判断能力；以供应商文档、显式配置及实际响应为依据。

### 3.2 模型角色

- 默认聊天模型：用于新建会话，支持在会话中覆盖。
- 标题生成模型：用于首次回答完成后生成短标题。
- 历史压缩模型：用于生成上下文摘要。
- 三个角色可以选择同一个模型，也可以使用不同供应商的不同模型。
- 标题和压缩模型未单独配置时可继承聊天模型，设置界面清楚显示继承关系。
- 修改全局默认配置只影响新会话；已有会话保留自己的选择。
- 新对话默认接着最近使用过的聊天模型：切换模型即记入“最近使用”，一次回答真正跑完再置顶，停止或报错不计入；设置提供“新对话使用最近使用的模型”开关，关闭后严格按默认聊天模型。记录中的模型被删除时自动跳过，删除模型时一并清理收藏与最近使用记录。
- 分支上的模型不可用时（对话建在还没有任何模型时，或该模型在设置里被删了），应用自动把分支改指到一个可用的模型，顺序是最近使用、默认聊天模型、任意模型；没有明确选择时优先挑名字或模型 ID 里带 flash、luna 的型号，连接全被停用时也照样能挑（停用不阻断发送）。模型按钮因此不会空着，用户不必先去设置里补模型才能继续对话；自动换模型时要有提示（“原有模型暂不可用，已自动切换到 X”），让用户知道老对话为什么换了模型。
- 聊天顶栏在“模型名 | 连接名”之后用一个小字显示当前分支所用的角色预设名（形如“·鲸鱼娘”）；按提示词内容与预设匹配，认不出即为自定义提示词，不显示。
- 输入框底栏：附件、角色预设、联网开关在左，模型选择与思考等级贴在发送按钮左边；角色预设按钮的文字是当前分支用的角色名，认不出时显示“自定义提示词”；联网开关为纯文字标签（“已联网”“未联网”）。模型选择与思考等级并排显示，都没有边框，也没有分隔线；模型按钮不显示下拉箭头、连接名用弱化色，两半悬停时背景色相同；思考等级获得焦点时不画焦点框，焦点提示由输入框整框的强调色描边承担。角色预设按钮的文字用正文色，右边配一个弱化的下拉箭头。输入框占位文本写明“Ctrl+I 聚焦，Shift+回车换行”。
- 输入框的模型选择器需要收藏与最近使用：模型列表改为自绘浮层（原生 select 无法在每行放置按钮），自上而下为“收藏”“最近使用”“全部模型”，最近使用与收藏去重，全部模型保持完整列表；键盘可上下移动、Home/End 跳到首尾、Enter 选择、Esc 关闭。
- 每次请求记录实际使用的模型、连接及参数快照，方便解释历史消息与费用。

### 系统提示词库 / 角色预设

- 提供通用助手、编程助手、写作助手、翻译助手和鲸鱼娘初始预设，可新增、编辑、删除并设置新对话默认角色；鲸鱼娘的系统提示词是内置常量（`WHALELADY_SYSTEM_PROMPT`），与角色库解耦，角色被删除后提示词依然可用。新增的内置角色不随升级自动补进旧用户的角色库（升级不改动已有数据），旧用户点一次“重置预设角色”即可补上。
- 新增的角色卡片排在已有角色卡片之前。
- 删除角色与重置预设角色前都要先向用户确认；
- 页面底部提供“重置预设角色”：程序自带的角色按固定 id 恢复成默认的名称与提示词，被删掉的补回并追加到末尾；用户自己添加的角色（id 不在其中）原样保留，位置与改过的内容都不受影响。
- “新对话默认角色”下拉不得出现两个“通用助手”：角色库里有该角色时只显示角色本身，没有时才显示兜底的“通用助手（内置提示词）”。库里有该角色而默认值为空时，默认值归一为该角色 id。
- 在会话选项中选择预设，将提示词复制到当前分支；仍可手动编辑，修改库不会追溯改变已有分支。
- 新分支继承创建时的系统提示词；提示词库随本地数据库和结构化备份保存。
- 升级缺少角色库的旧数据时添加初始预设，保留已有会话提示词；用户主动清空的库保持为空。

### 3.3 能力与参数

- 模型能力包括：文本、图像、视频、音频、PDF 输入，流式输出，推理等级或预算，原生搜索、工具调用和采样参数。新增 Gemini 模型默认启用图像、视频、音频、PDF、工具调用、原生搜索；新增 Qwen 模型默认启用图像、视频、工具调用、原生搜索。
- 不支持的能力禁用并说明原因；参数按协议转换，只发送该模型支持的字段。
- 思考设置按模型展示供应商实际支持的枚举、预算或自动选项；不存在统一可用的等级表。
- 温度和 `top_p` 在会话选项中按当前分支保存，并仅在模型和协议支持时发送；最大输出 token、系统提示词等使用对应的模型或会话设置。
- 不同协议中的系统指令使用各自正确的字段或角色，保留可追溯的请求构造逻辑。

## 4. 聊天与消息版本

### 4.1 基础交互

- Markdown 渲染支持代码块、语法高亮、列表、表格、链接；数学公式为可选增强。
- 提供复制消息、复制代码、停止生成、重新生成、重试、消息编辑、“从此回答创建分支”和查看该回答的请求详情；这些操作同时可从问答消息的右键菜单进入，会话列表项右键打开与“…‬”相同的菜单。
- 回答最终正文支持按 Markdown、纯文本、富文本三种格式复制：纯文本必须去掉 Markdown 标记并保留可读结构（列表保留圆点或编号、表格按 tab 分隔、代码块去掉围栏），富文本写入 HTML；存在文字选区时，菜单先把选区的纯文本与富文本复制放在最前面。
- 拖动侧栏宽度不得选中侧栏或消息文字，消息文字仍可正常选择。
- 支持流式文本、推理摘要和工具事件；中断保留已有内容并标注状态。
- 同一会话首版只允许一个聊天生成任务，多会话并发采用可配置的有限队列。
- 正在生成时切换会话不丢失任务；退出时提示仍有任务，并允许取消后退出。
- Enter 发送、Shift+Enter 换行，可在设置中反转；中文输入法合成期间 Enter 不发送。

### 4.2 分支与版本规则

- 编辑已发送的用户消息并确认发送后，从该节点创建新分支；原消息及原后续回答保留。
- 编辑助手回答创建带“手动编辑”标记的新版本；该版本可以成为后续上下文。
- 重新生成创建同一父节点下的新助手版本，不覆盖旧回答。
- 消息旁显示版本编号和前后切换入口；切换分支时消息区和大纲同步变化。
- 切换旧版本后继续提问，沿所选分支继续；上下文仅使用当前分支中选定的消息。
- 生成中禁止修改该任务依赖的消息，提示先停止生成。
- 有工具调用的回答被手动编辑后，保留原始工具证据及修改标记；请求上下文按协议正确构造，不将旧工具结构冒充为新生成内容。
- 首版可不展示完整分支树，但数据结构应包含父节点和版本关系。

### 4.3 从模型回答创建分支

- 每条已完成的模型回答提供“从此回答创建分支”操作，包括重新生成的旧版本和手动编辑版本。
- 新分支属于同一会话，继承当前路径从起点到所选回答的全部历史；不包含该回答之后已有的提问和回答。
- 创建后切换到新分支，输入框获得焦点，用户可以输入不同的后续问题。创建及切换分支本身不发起模型请求、不产生推理费用。
- 可以从同一回答创建多个分支，也可以从任意分支的后续回答再次分支；各分支独立继续，原路径完整保留。
- 会话标题用于左侧会话列表；分支另有名称，默认“主线”“分支 1”“分支 2”，可以重命名。创建分支不新增左侧会话，也不重新触发会话自动标题。
- 中间顶部提供当前分支名称及分支选择器，选择器显示名称、来源回答摘要和最后更新时间。回答处提供分支数量及快速切换入口。
- 切换时恢复各分支的输入草稿和阅读位置，并同步更新消息、大纲及当前模型设置。
- 新分支继承创建时的模型、系统提示词、思考参数和搜索模式；之后的设置修改只影响所选分支的后续请求。
- 共享历史节点不可就地覆盖；编辑共享消息生成新版本及路径，其他分支继续引用原版本。附件、工具证据和协议状态按来源节点保存。
- 分支上下文只包含从根节点到该分支当前节点的路径，不能混入兄弟分支内容。使用 Responses 等服务端会话状态时，同样核对续接状态属于选定路径。
- 仅当摘要完整覆盖共享前缀且版本仍一致时才可复用；跨过分叉点的其他分支摘要不可复用。
- 空分支也要持久化；重启后恢复分支名称、来源、配置、草稿及最后选择的分支。
- 删除分支需确认删除范围，不影响其他分支共享的历史或附件；包含后代分支时明确列出影响范围，最后一个分支不能单独删除。
- 同一会话仍只允许一个聊天生成任务。生成中可切换查看其他分支，任务持续写入发起时的分支；创建分支只能选择已完成回答，新任务需等待当前任务完成或停止。

示例：用户询问“如何开发聊天客户端”，模型给出技术方案。用户从该回答创建“Electron 实现”和“Tauri 评估”两个分支，分别继续讨论。两个分支共享此前历史，各自的后续消息互不进入对方上下文。

### 4.4 图片与文件附件

- 图片可通过图片按钮、粘贴或拖放添加；“上传附件”支持选择常见文件。每条消息最多 6 个附件，每个文件最多 10 MB。
- 其余文件保存在本地附件目录，支持预览、移除和备份恢复。
- 图片在发送前处理一次：长边超过 1280 像素的按比例缩小（不放大小图），体积不小于 50 KB 的用 `@aurouscia/image-compress` 压成 WebP，以省下请求体与 token。小于 50 KB 的图原样保留，不重编码。动图（GIF 动画）原样保留：DeepSeek、Qwen3+ 只读第一帧，转成静态图等于白转，而支持动图的模型（GPT-5.6、GPT-6、Gemini 3）需要原始动图。附件查看器的复制与保存同样输出 WebP。
- 模型设置可分别配置图片、视频、音频和 PDF 输入能力。支持的类型按协议原生编码后发送。
- 当前模型不支持的附件尝试用 `@firecrawl/anydoc` 从内存转换为 Markdown，再连同用户提问发送给模型；转换文本受长度上限约束，纳入上下文预算。纯文本直接输入。
- `@firecrawl/anydoc` 在本地支持 PDF、Word、PowerPoint、Excel、OpenDocument、RTF、EPUB 和 CSV，不支持视频或音频转换；扫描版 PDF 需要 OCR，本地转换失败时清楚报错，不默默丢弃附件，也不会默认将文件上传到 Firecrawl。
- 附件原文件保存在本地，转换出的 Markdown 随消息保存；导出、备份及删除需正确处理附件引用。

## 5. 推理信息、工具与联网搜索

### 5.1 推理展示

- 仅展示 API 实际返回且允许展示的推理文本或摘要，不承诺获取模型完整内部思考过程。
- 推理区默认可折叠，区分推理摘要、回答正文和工具执行。只展示服务返回的内容，不推测内部思考。OpenAI 兼容协议下同时读取 `reasoning_content` 与 Ollama 的 `reasoning` 两个字段名，否则 Ollama 思考模型（如 gemma4）的思考内容会被整段丢弃。
- 模型不返回可展示推理时显示能力说明，不生成伪造思考内容。
- 按供应商约定保留后续轮次所需的推理签名、加密状态或其他不透明数据，不允许用户直接编辑。

### 5.2 搜索模式

联网搜索和读取网页分别配置。联网搜索支持自动联网、关闭、模型原生搜索、Exa、Ollama Cloud Web Search、Tavily、Firecrawl、AnySearch 和 DeepSeek 搜索。新对话默认自动联网，优先原生搜索，其次按 Tavily、Exa、Ollama Cloud、AnySearch、Firecrawl 的顺序选择已配置 Key 的外部提供方；没有搜索 Key 时自动使用 Tavily 的免 Key 搜索。Tavily 排在最前，因为它的响应明显快于 Firecrawl。Tavily、Firecrawl 和 AnySearch 也支持手动选择免 Key 模式。原生搜索取决于模型及协议支持；外部搜索由桌面主进程编排，并保存真实来源。

- 新对话的默认搜索模式在“设置 → 联网搜索 → 默认联网搜索”中指定，默认“自动联网”；之后每个分支仍可单独调整，切换模型时保留显式的“关闭”并回到该默认值。
- 新对话的默认读取网页方法同样可配置，默认“自动”，另提供“上次使用”：新对话接着最近一次在会话里选择的读取方式记录该值，尚无记录时回落到自动。
- “自动模式下优先使用模型原生搜索”默认开启。关闭后自动模式改为先选择外部搜索服务，原生搜索只作最后兜底。该偏好只决定自动模式的降级顺序，不覆盖会话里显式选择的模式；模型不支持原生搜索或不支持工具调用时，请求自动落到可用的一侧。
- “自动模式下优先使用的外部搜索”决定外部搜索链的第一项，默认“默认顺序（内置）”。界面将未配置 API Key 的选项置灰，但已保存的值必须容错：密钥被删除或从无密钥备份导入时跳过该家继续降级——Tavily、Firecrawl、AnySearch 支持免 Key，只有 Exa 与 Ollama Cloud 强制要求密钥。该偏好只作用于联网搜索，不改变读取网页的自动降级顺序。

- 模型原生搜索：传递供应商要求的工具或参数，消费返回的搜索事件和引用。
- Exa、Ollama Cloud Web Search、Tavily、Firecrawl 和 AnySearch：在联网搜索设置中配置可选 API Key 与结果数量；Ollama 搜索可复用 Ollama Cloud 连接密钥。Tavily 无 Key 时发送 `X-Tavily-Access-Mode: keyless`；Firecrawl 和 AnySearch 无 Key 时使用官方匿名请求。所有外部搜索均由模型工具调用触发，因此要求所选模型支持工具调用，并在设置中说明。
- DeepSeek 搜索与抓取：分别调用 `POST /v1/tools/search` 与 `POST /v1/tools/fetch`（Base URL `https://api.deepseek.com`），共用一份密钥——设置中单独填写，留空时复用主机名为 `api.deepseek.com` 的连接密钥。两者按成功请求次数计费（每 1000 次 5 元，账号级 5 QPS），因此必须显式选择，不参与自动降级；界面需在选项与说明中标注按次计费。402 视为余额不足并给出充值提示。
- 后续可增加强制搜索模式，在推理前主动检索；不要混淆其与模型自主搜索的行为。
- 默认一次请求只选一种搜索模式，避免重复调用；工具执行次数、耗时和返回长度有上限。
- 搜索失败可有限重试；继续回答时标明没有成功获得搜索结果，不伪造引用。
- 原生搜索不可用时提示选择其他方式，不无提示地转发到不同搜索供应商。
- 输入框联网按钮同时开启或关闭联网搜索和读取网页；会话选项中仍能单独调整两项。

### 5.3 工具事件与引用

- 展示工具名、状态、开始时间、耗时、可读输入、结果摘要和错误；详细结果折叠。
- Responses 协议请求显式带上 `store: false`：省略时 OpenAI 默认把回答存到服务端并不再返回思考内容，思考摘要会因此不显示；本地优先的客户端不应把对话留在 OpenAI 那边。
- Responses 协议的思考事件名两家不同：OpenAI 发 `response.reasoning_summary_text.delta`（摘要），DeepSeek 发 `response.reasoning_text.delta`（思维链原文），两种都要读取；Responses 服务的流式帧可能在 `data:` 之前多一行 `event:`，两种帧格式都要支持。
- 引用显示来源标题、URL，能定位关联引用并在系统浏览器打开。来源列表默认收成一行（显示条数），点击标题才展开全部条目——一次搜索能带回十几条，全部铺开会把回答区撑得很长。
- 工具结果和网页内容视为外部资料，不能改变应用权限、执行命令或读取本地文件。该提示写在搜索与读取网页两个工具的描述里（`UNTRUSTED_CONTENT_NOTE`），四种协议一致；系统提示词按用户所写原样发送，不追加任何工具或联网相关片段，因此改提示词不会把这层防护删掉。
- 读取网页默认自动按 Tavily Extract、Exa Contents、Ollama Cloud `api/web_fetch`、AnySearch Extract、Firecrawl Scrape 的顺序调用已配置密钥的服务；然后尝试 Tavily、AnySearch、Firecrawl 的免 Key API。服务失败时继续尝试下一个；都不可用或都失败时回退到本地读取网页。Tavily 免 Key 时发送 `X-Tavily-Access-Mode: keyless`；Firecrawl 与 AnySearch 不发送 Authorization。Ollama Cloud 可复用连接配置中的 API Key。
- 用户可在会话选项中为读取网页指定自动、任一供应商、本地读取网页或关闭。无 Key 的 Tavily、Firecrawl 和 AnySearch 仍可选用。旧会话没有此字段时，若原搜索模式为关闭则读取网页保持关闭，否则按自动处理。
- `web_fetch` 通过 Electron 主进程提供。供应商读取网页 API 返回 Markdown；AnySearch 返回 HTML 时使用 Defuddle 转换。本地读取网页使用 Electron `net.fetch`（Chromium 网络栈）并服从默认 session 的代理配置，请求优先声明 `text/markdown`，HTML 使用 Defuddle 提取并转换为 Markdown。
- Gemini 原生 Google Search 和自定义 `web_fetch` 同时启用仅支持 Gemini 3 及更新模型；较早 Gemini 模型选择外部搜索提供方时可使用 `web_fetch`。
- 发送给读取网页服务前验证目标为 HTTP/HTTPS 公网地址。使用本地读取网页时逐跳检查重定向，最多 5 次，不允许 HTTPS 降级；响应体上限 2 MB、返回正文上限 20,000 字符。
- 首版工具权限仅限已实现的搜索、网页抓取和本地日期时间工具，不开放任意代码、shell 或文件工具。
- `datetime` 为本地只读工具：无需参数，返回本机日期时间、星期、时区偏移和 UTC 时刻，不产生引用来源；涉及当前日期时间的问题应调用它而不是凭记忆回答。标题生成和历史压缩等后台请求不提供该工具。
- 每个客户端工具单独计算调用额度（默认每次回答 30 次），额度用尽的工具不再下发给模型，其他工具的额度不受影响；模型原生搜索由服务端触发，不计入该额度。
- 持久化工具调用 ID、参数、结果及协议所需对应关系，保证多轮请求可继续。

## 6. 自动标题

- 首次助手正文成功完成后触发一次后台标题生成，不阻塞继续聊天。
- 输入使用首轮用户问题与助手回答的限长文本；无需把全部附件再次发给标题模型。
- 生成约 8–20 个中文字符或同等长度短标题，语言跟随会话内容，过滤多余引号和格式。
- 首轮生成失败、取消或没有正文时不触发；下一次有效完成后可以触发。
- 标题任务失败时保留基于问题的临时标题，允许手动重新生成。
- 后台任务提交结果前核对会话仍存在、标题未被手动修改及请求版本仍有效。
- 标题请求单独计入 token 和费用记录；避免重复触发及无限重试。

## 7. 历史压缩与上下文构造

- 原始消息始终保存在本地；压缩只改变发给模型的上下文。
- 按系统指令、历史消息、附件和工具结果估算输入上下文；最大输出作为生成上限单独发送，不从上下文窗口中预扣。
- token 计算区分准确计数与估算，界面不把估算值呈现为精确数值。
- 输入上下文接近阈值时自动摘要较早消息，并保留最近若干轮；支持手动触发。供应商仍可按自己的规则拒绝输入与输出组合。
- 摘要覆盖目标、事实、约束、偏好、重要结论、待办和来源引用，不能添加未经对话支持的事实。
- 压缩完整的对话或工具调用单元，避免留下孤立工具结果或缺失调用。
- 每份摘要记录所属分支、消息范围、源消息版本、生成模型及时间。
- 编辑或切换已摘要消息时失效相关摘要，并按当前分支重新构造上下文。
- 换用更小上下文窗口模型后重新预算；必要时重新压缩。
- 压缩失败明确反馈，允许重试或选择可行模型；不静默截断重要上下文。
- 在会话中提供“已压缩上下文”提示和摘要查看入口，并区分人工消息与系统摘要。

## 8. 本地数据、隐私与安全

- 提供 Linux deb 打包。桌面项的 `Name=Seekie Chat`、`Comment=Seekie Chat with DeepSeek LLM`、`StartupWMClass=com.github.shellexy.seekie-chat`，由 electron-builder 从打包配置生成，不维护独立的手写文件。`StartupWMClass` 依赖 package.json 的 `desktopName` 与窗口 `WM_CLASS` 一致，否则桌面环境无法把运行中的窗口关联到启动器。
- 程序名统一为“Seekie Chat”：窗口标题、侧栏顶部、加载页、页面标题、备份文件名与导入对话框都用这个名字。配置目录随之为 `~/.config/Seekie Chat`（Electron `appData` 下），可用 `SEEKIE_DATA_DIR` 指向别处；调试用环境变量是 `SEEKIE_DEV_URL` 与 `SEEKIE_DEBUG_REQUESTS`。改名前的旧目录不再读取，不做数据迁移。
- 程序与任务栏图标为 `build/icon.png` 的彩色版；新建对话页为 `build/welcome-icon.png` 的线稿版（白底转透明、只留黑线），以 128×128 显示，用 CSS mask 使线条由品牌蓝 `--accent` 着色，与两种主题底色的对比度均不低于 3:1；侧栏顶栏不显示图标。

- 使用 SQLite 保存会话、分支、消息、工具事件、摘要及任务状态；附件单独存放。数据库由主进程直接读写（WAL，退出时 checkpoint），会话、分支、消息按实体各占一行，保存只写内容变化的行，流式生成期间只更新正在生成的消息；渲染进程不得访问数据库。渲染层只接收正在生成的那条消息（增量补丁，带修订号以拒绝过期内容），附件字节在需要显示时按 id 获取，避免每次刷新都复制整份状态。
- API Key、Exa、Ollama、Tavily、Firecrawl、AnySearch Key 和自定义请求头默认保存到数据目录的 credentials.json，采用原子写入及 0600 文件权限，重启自动加载；界面说明其为明文保存。仍可选择仅当前运行或使用系统安全存储加密保存。
- 日志、错误面板和导出默认脱敏 API Key、认证请求头及其他秘密。
- 渲染进程不直接管理密钥和网络；Electron 启用上下文隔离、关闭页面 Node 集成，通过受限 IPC 调用主进程。
- 消息 HTML、Markdown 链接、图片路径及工具返回值经过校验；外链只允许明确支持的协议。
- 自定义 Base URL 支持本地服务，连接测试显示目标地址；首次把密钥发送到新配置目标时提供清楚的目标信息。
- 聊天、标题、压缩分别展示数据会被发送给哪个连接；跨供应商配置不能隐藏这一事实。
- 搜索会将查询发给搜索供应商；不因启用搜索上传全部聊天记录。
- 默认无遥测；若后续加入，需明确说明并允许关闭。
- 支持 Markdown 导出及包含分支和附件信息的结构化备份，导出默认不包含密钥。
- 提供应用内请求详情查看入口：显示该回答实际发送的请求地址、请求头和请求体，**以及上游返回的原始内容**（流式原文，便于核对服务实际返回了什么），失败请求附上游返回的报文；请求头与请求体按 JSON 语法着色，键名、字符串值、数字、布尔各用一种颜色，标点用弱化色，键与值必须一眼能分得开；深色主题用另一套提亮过的颜色。请求体、响应内容与上游返回各自是可折叠的块，默认折叠但用 `::details-content` 露出开头几行，旧版 Chromium 退化为普通折叠；密钥、自定义请求头等凭据必须脱敏后才会到达渲染进程（保留头名称，便于核对）。上游原文过长时只记录前 200,000 字符并标注截断。
- 请求记录随对话持久保存（数据目录下的独立文件，不与数据库同文件，不进入导出与备份，有总量上限并按最旧优先清理，删除会话时删除），以便重启后回看；附件等二进制内容在记录时折叠为长度占位。
- 支持备份恢复，以及异常退出后的部分回答恢复。不支持旧版数据库格式的升级。

## 9. Linux 本地运行与可靠性

- 优先在当前 Linux 开发环境验证 Electron 本地运行，检查 X11、Wayland 下的关键交互。
- 提供依赖安装和开发启动命令，例如 `npm install`、`npm run dev`，在 README 说明 Node.js 版本及必要的系统依赖。
- 开发启动同时管理前端开发服务和 Electron 生命周期；退出后清理相关进程。明确本地数据库、附件和日志路径，重启开发进程不清空用户数据。
- 验证中文字体、输入法、剪贴板、拖放、高 DPI、窗口尺寸恢复及键盘导航。
- 支持系统代理与可选应用级 HTTP/SOCKS 代理；具体代理类型需随所用网络库验证。
- 网络任务支持取消、超时、断线反馈；尊重服务端限流及 Retry-After。
- 已接收部分流式内容后不自动重发整个请求，避免重复费用及重复消息；让用户明确重试。
- HTTP 401/403、429、5xx、参数不支持、模型不存在、余额不足分别给出可操作说明。
- 崩溃恢复时将未完成任务标为中断，不自动发起新的收费请求。
- 当前不要求安装包、发布签名、发行版分发及自动更新；这些需求留待后续单独确定。

## 10. 建议技术结构

- Electron 主进程：密钥、网络、工具执行、SQLite、文件和任务生命周期。
- React + TypeScript 渲染进程：三栏布局、设置、消息和状态展示。
- 统一模型适配层：聊天请求构造、事件归一化、能力声明与错误转换。
- 统一事件至少覆盖正文增量、可展示推理增量、工具开始/完成、用量、完成和错误。
- 数据层使用消息父节点及版本关系，避免把当前界面上的线性消息列表当作唯一存储。
- 上下文构造器集中处理分支选择、协议转换、工具关联、摘要和 token 预算。
- 后台任务区分聊天、标题、压缩及搜索，支持取消、恢复状态与并发限制。

## 11. 分阶段范围

### 阶段一：可日常使用的基础客户端

三栏布局、浅色主题、四种 API 协议、连接和模型设置、三个模型角色、流式聊天、图片、自动标题、重命名、消息编辑、回答版本、从回答创建分支及分支管理、本地保存、基础错误反馈和 Linux 本地开发启动。

### 阶段二：完整上下文与工具体验

可展示推理、思考参数、原生搜索、Exa、工具事件与引用、自动和手动历史压缩、备份恢复、代理和用量统计。第一阶段即预留这些能力的数据结构。

### 阶段三：体验增强

全文搜索、置顶、快捷键配置、数学公式和完整分支树可视化。打包、分发及自动更新不在当前阶段范围内。

这只是交付顺序建议，第二阶段功能仍属于用户要求的整体目标。

## 12. 验收场景

1. 分别配置四个协议并完成多轮流式对话；模型列表获取失败时仍可手动添加模型。
2. 选择不同的聊天、标题、压缩模型，确认三类请求各自使用正确配置。
3. 首次回答完成后自动改名；生成标题期间手动改名，后台结果不得覆盖。
4. 左侧有大量会话时可独立滚动，中间阅读位置不变化；大纲点击可正确定位。
5. 编辑较早提问、编辑回答、重新生成并切换旧版本后继续聊天，旧分支完整保留。
6. 重启应用后消息、版本、附件、引用及手动编辑标记正确恢复。
7. 图片模型可以接收附件，纯文本模型不能静默丢弃附件。
8. 分别使用可支持的原生搜索和 Exa，显示工具状态及真实引用；搜索失败不生成虚假来源。
9. 模型不提供推理摘要时不会展示捏造的思考内容；不支持的思考参数不会被发送。
10. 压缩后原始消息仍可阅读；编辑摘要覆盖的旧消息后，过期摘要不再进入请求。
11. 断网、停止生成、退出和崩溃保留已收到内容，重启不会自动重发收费请求。
12. 中文输入法确认候选词不会意外发送消息；Wayland/X11 下剪贴板、缩放和外链可用。
13. 导出和诊断日志不包含密钥；Linux 系统密钥环不可用时明确提示实际保存方式。
14. 从同一回答创建两个分支并分别继续提问，请求只包含各自路径；创建分支本身不调用模型。
15. 分支重命名、嵌套分支、切换草稿、配置隔离及重启恢复正常，左侧仍只有一个会话条目。
16. 编辑共享历史或删除其中一个分支，其他分支的消息、附件及工具记录保持完整。
17. 从旧回答版本创建分支时使用该版本对应的历史及协议状态，不误用最新回答或其他分支的摘要。
18. 按 README 安装依赖并运行开发命令可启动 Linux 桌面窗口，无需打包；退出后开发进程正常清理，再启动能恢复数据。

## 13. 当前建议默认值

仅本地保存；无账号与同步；Electron；浅色主题；中文界面优先；新会话继承默认模型；默认自动联网；推理展示折叠；上下文压缩在接近预算时启用；首版不执行任意外部工具。

本地开发前仍需确定：模型及供应商优先适配名单、Exa 具体检索能力和预算，以及首版交付是否同时包含阶段二。目标发行版、CPU 架构及打包方式留待后续确定。

### 回答时间与用量详情

- AI 回答前不显示头像和模型标签；操作按钮右侧合并显示“模型名称·YYYY-MM-DD HH:mm · 输入 · 输出”，悬停、键盘聚焦或点击时在同一个浮窗内先显示模型名字、模型提供方、思考等级与角色预设名（同一行）、日期时间，再接用量详情（总耗时、速度、生成速度、首字耗时）；用户提问下方显示同一格式的日期时间。
- 回答下方 token 文字仅显示“输入 · 输出”；支持悬停、聚焦和点击展开详情：输入、输入（缓存）、输出、速度（tps）、首字耗时（s）。点击保持展开，再次点击、Esc 或外部点击关闭。
- 输入为总输入 token，缓存为其中的命中读取量；Anthropic 总输入包含普通输入、缓存读取和缓存写入。多轮请求按轮累计，轮内累计事件不重复计数。
- 速度为输出 token / 本次生成总秒数，包含思考、网络、工具调用，排除请求前的历史压缩。首字耗时计至第一段正文返回。Gemini 输出包含服务返回的思考 token。
- 用量与计时持久化到消息；旧消息缺少计时、服务未提供缓存统计或任一轮缓存统计缺失时显示“未提供”。输入框隐藏模型选择及思考等级前的图标，effort 等级按原文显示；新增 GPT 模型的等级列表包含 `xhigh` 和 `max`，DeepSeek 为 `low`、`high`、`max`；多段推理各自记录并显示耗时。
